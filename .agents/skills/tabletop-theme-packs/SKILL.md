# 冷知识主题题包

## 找到项目与本次范围

先检查当前项目的设计、题包目录、题包登记、数据类型和测试。该项目最初位于D:/西安电子科技大学/闲来没事干点活/tabletop-party-web；若迁移，以当前工作区真实文件为准。不要仅凭旧路径新建第二个应用。

用户已给出主题时直接推进。数量未指定时以一个完整题包90题为目标，分批核实；用户指定20题就交付20题并说明容量，不擅自补到90题。新增数据不包含发布网站、改变计分或安装依赖的授权。

先阅读[题包数据契约](references/pack-format.md)。若项目已有不同格式，沿用实际格式并将下述检查映射到已有字段；不要为了模板重构应用。目前项目可能只有设计文档，此时交付独立题包数据和接入说明，不能声称已经接入不存在的界面。

## 保留已确认玩法

- 每人不同词，普通玩家看真实解释，一名瞎掰人只看词并编造。
- 默认读卡10秒，可设置时间；解释允许更长，不要求读完或逐字复述。不要将解释自动压成20至40字。
- 普通玩家用记住的真实信息解释；瞎掰人编造。题目要给两者合理发挥空间。
- 主题包支持单选、多选组合；同一知识点跨包只保留一份，别名不算新题。
- 稳定conceptId关联跨局历史，修改措辞不能随意换ID使旧题变成新题。

## 选题与核实

围绕主题选择多数人不熟悉、真实存在、词名有想象空间的知识点。题内给一个明确核心含义，再补真实细节；允许读不完，但不用无关铺垫凑长度。避免一个包内大量答案只是“某地的一种植物”等模板，避免把生僻字数量当难度。

使用联网检索核实每一题，优先博物馆、研究机构、大学、政府文化资料和原始研究；开放知识库适合发现候选词，再检查其引用。搜索摘要、其他模型生成内容和未经核实的随机问答不能单独作为正式答案依据。每题保留实际阅读过、直接支持关键事实的链接、标题和核实日期。可用一个来源支持多题，但必须确实包含相应事实。

分清词义、民间传说和学术假说；有多义时明确采用的词义。无法核实的题留在草稿，不进正式可抽题池。来源打不开时换来源；不要编造链接或用形式校验代替事实核验。用自己的话整理解释，不照抄商业桌游卡片或长篇来源文本。

## 去重、数据和接入

对照全库检索词名、别名和已有概念；相同概念复用conceptId。只是追加题包归属时引用原题或合并packIds，不能复制成新的可抽题。不同含义明确区分，但不要利用多义制造歧义题。

正式题status为verified；草稿为draft。草稿不可被登记为可抽题。保持已有ID及历史记录，不在扩充题包时清空已玩历史。每包保存版本和实际数量；组合题池合并后按conceptId去重，再排除已见历史。

使用本技能JSON契约时运行：

```powershell
python "<skill-dir>/scripts/validate_pack.py" "<pack.json>" --existing-dir "<existing-pack-directory>"
```

没有已有目录时省略该参数。脚本只做结构与精确概念冲突检查，不检索网页、不证明解释真实，也不能替代语义去重。按实际题库补查别名和近似词义。现有项目采用TypeScript题卡时运行其原生测试，不强制改JSON。

接入已有应用时更新题包登记、数量展示、选择页可用量及必要测试；不要改其他题包正文。至少验证单选仅抽中本包、多选不重概念、草稿不抽取、历史仍生效。N人一圈需要N*N条去重可用题；完整包90题足够9人一圈81题，重复游玩后仍可能题量不足。容量不足必须如实提示，不能自动重复本局题或缩短局长。

## 交付

报告新增/修订题包、已核实数量、草稿数量、跨包复用情况、实际接入状态、验证结果和文件路径。明确尚未验证的事实或尚未发布的状态。只在用户要求或已授权的发布范围内更新线上站点。
