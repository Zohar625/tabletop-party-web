# 项目决策与后续约束

## 2026-10-25：暂不开发登录与云存档

用户明确决定：登录与云存档方案先记下，今后有必要再设计；当前不开发、不接入服务。

- 现阶段保持游客直接游玩，保留现有本机自动存档与恢复功能。
- 不因为新增长局桌游就自动增加账号、登录、云数据库或第三方邮件服务。
- 将来确有跨设备续玩、长期存档或数据恢复需求时，再与用户评估是否需要登录。
- 若届时实施，优先考虑可选登录：游客可玩、同设备仍可本机存档，只有云同步和跨设备恢复需要登录；不中断已开始的游戏。
- 此前讨论的 Supabase、邮箱验证码、本机与云双存档仅为备选思路，尚未选定服务或批准实施。
- 多人整桌存档需另外设计房主与座位恢复，不把单人云存档当作多人恢复已完成。
