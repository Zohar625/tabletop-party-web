# 制图师：目标导向教学、3D沙盘与协会委托设计草案

日期：2026-10-25
状态：待用户确认本轮改版方案。尚未修改运行代码或安装3D依赖。

## 用户反馈与目标

用户在现有教学结束后仍不清楚游戏目标。希望地图有3D收藏感，能明显看到季节变化，并把皇家敕令呈现为冒险者协会式UI。

第一优先级：玩家在第一次落笔前能说明目标；首次落笔后能解释为何该位置得分。3D与协会界面围绕这件事组织，而不是增加新的规则负担。

## 一句话玩法

按照翻开的探索牌，在四季里规划自己的地图，争取当季两项委托的声望；金币增加收入、怪物周围空格扣分，冬季结束计算最终成绩。多人比较累计声望及原规则平局条件，单人根据目标难度折算评级。

## 方案选择

推荐真实3D的低多边形微缩沙盘：模型像桌上的树、屋子与山峰积木，既能清晰选格，又适合完局欣赏与保存。

备选为写实自然景观：视觉更接近真实山河，但加载、手机性能与地形辨识成本更高。本轮采用微缩沙盘，不增加写实大模型或外部素材下载。

## 1. 目标导向的短春季教学

替换现有逐功能八课为一个有因果关系的短春季体验，保留深入规则帮助：

1. 从协会接到第一份具体委托：“地图边缘每个森林格计1分”。先展示目标与好坏两个位置的得分预览。
2. 玩家选择森林形状；提示可得分的边缘和不贡献本目标的内部空格。玩家落下第一笔，明确显示本次改变了哪些格、目标预计增加几分。预计分与已结算声望分开。
3. 第二次探索引入旋转和镜像，让玩家用新形状争取更多分数；不先展示所有工具说明。
4. 展示第二项当季委托，让玩家尝试在两个目标之间取舍。四张委托保留规则上的随机与轮换，在教学中使用固定例题。
5. 山峰围合、金币、遗迹与替代格、怪物各用局部演示与真实放置练习解释，说明其对当前目标/季末的影响；避免只点击“下一步”就算学会。
6. 完成一次实际季末计分：逐项高亮委托贡献区域、金币和怪物相邻空格，分别说明本季声望的来源。揭示下一季生效目标变化，地图与金币继续保留。
7. 进入正式游戏前给一次自由落笔任务，要求玩家自行选择能增加当前委托分数的位置；可查看提示、重试或退回演示，不使用随机处罚或限时。

教学练习独立于正式存档，所有合法性与得分计算复用正式引擎。每一步能重试、返回或退出，清楚显示“当前要做什么”和成功反馈。

## 2. 真实3D微缩沙盘

使用Three.js WebGL，模型由程序化基础几何构建，避免依赖外部模型或3D素材站。

- 11×11棋盘保留原坐标与规则，格子是有厚度的小地块；森林竖立树木、村庄为红顶小屋、农田有垄沟、水域有浅水面、山峰形成高低起伏、怪物有独立模型。
- 默认是清晰的斜俯视正交视角，提供“俯视落笔”和“欣赏沙盘”切换。落笔模式保持稳定相机，点击地块后确认；欣赏模式允许旋转、缩放，拖动相机不提交位置。
- 高模型不遮挡后方落点：限制模型高度，必要时在预览/俯视时淡化遮挡物。选择与点击使用棋盘平面坐标，不依赖细小树叶/屋顶的命中。
- 保留现有二维地图作为明确标注的兼容视图；WebGL不可用或用户主动切换时仍能完成同一局。
- Three.js按需加载；限制像素比、阴影与模型数量，重复模型共享资源或实例化，后台暂停渲染；退出时释放GPU资源。减少动态效果偏好禁用装饰性运动。
- 原有存档与联机数据继续用格子状态，3D不进入规则引擎，不改变牌序、计分或其他桌游。

## 3. 四季能看出来，也不干扰识别

春季新绿、盛夏浓绿与饱满农田、秋季金橙树叶和收获色、冬季树冠与屋顶积雪及冷色光感。

季节切换使用短暂光色与材质过渡；模型出现有落地/生长反馈，金币与结算有适度动画。天气仅为视觉，不增加冻结、收成等额外规则。地形的基础色块、轮廓与图例保持可辨，冬季不会全部变成白色而看不清森林、水域和村庄。

## 4. 冒险者协会委托板

玩法中的皇家敕令，在展示层统一称“协会委托”，由木质公告板、纸质委托、印章与图标构成。原有四张目标及季节轮换保持。

- 一眼可见“本季结算”的两张，另两张注明下一次生效季节。
- 每张委托包含简短白话目标、一个小示例、当前预计声望；点开后高亮确实贡献分数的地图格。
- 放置预览时显示当前两项委托的预计变化，例如“边境植林 +2，林中高塔 +0”。落笔后反馈已更新；不把预览当作已到账积分。
- 委托是持续按图计分，不添加“接单后独占”“达标领取后移除”等新规则。季末展示结算印章与分数明细，同一委托按原规则可在另一个季节再次计分。
- 手机委托板可收起，当前目标摘要与落笔确认仍清楚可见；中文规则文字保持可读，不用装饰纹理压过内容。

## 5. 本机收藏

完局可把自己的地图加入本机收藏册，保存最终地图与四季快照，附日期、声望与头衔；支持旋转欣赏与图片导出。已有仅分数的历史仍保留，不伪造缺失地图。旧进度、战绩不因改版被清空。

遵守既有决定：本轮不开发登录、账号、云存档，也不引入用户必须注册的3D服务。收藏保存在当前设备，图片可自行下载长期保留。

## 技术边界与验收

- 扩展视图适配层，正式规则和网络协议只在确有必要时最小改动；2D/3D读同一份棋盘和预览。
- 现有存档可恢复，单人与联机均可切换视图，邻座伏击仍显示正确地图。
- 教学必须验证“理解目标并自行得分”的路径，而非仅验证按钮可点击。
- 检查3D坐标选格、相机拖动与落笔互斥、季节材质、模型资源释放、兼容视图与图片导出。
- 维持全量既有测试；增加目标预览与教学状态、收藏迁移和3D坐标映射的有意义测试。
- 真实浏览器可用时验收手机与桌面；不可用时如实记录未完成视觉/触控验收，不能以构建或SSR代替。
