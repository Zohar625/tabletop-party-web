# 桌游聚会网页开发计划

> For agentic workers: Use superpowers:executing-plans to implement this plan task-by-task after the design review. Do not dispatch subagents without user authorization.

**Goal:** 实现单手机冷知识瞎掰网页完整闭环。

**Architecture:** TypeScript纯规则负责阶段和计分，React负责界面，会话适配器隔离本地存档和未来联机。

**Tech Stack:** React、TypeScript、Vite、Node内置测试、localStorage。

**2026-10-22 实施状态：** 本地首版功能已实现，数据接入完成。10 项规则/存档测试、11 项 Python 数据测试及构建通过；浏览器审批服务 403 阻塞手机与点击验收，用户明确选择先保留本地版、不发布。下方原验收清单仍保留未验证的手动/发布项目，详见 `2026-10-22-implementation-status.md`。实际 Question 类型直接保留现有 sources 数组与可选历史字段，未转换成丢失证据的单 sourceUrl。

## 全局约束

- 以同目录2026-10-22-design.md为验收依据，实施前审阅补充默认值。
- 代码、依赖和产物保存在D盘，旧超级井字棋项目保持独立。
- 首版只实现单手机网页；联网只做清晰模块边界。
- 默认阅读10秒，预设10/20/30秒，自定义5至120秒；允许更长解释，不要求10秒内读完，不限制20至40字，不要求逐字复述。
- 按题材独立题包，支持多选组合；正式完整题包目标每包至少90题，容量不足明确提示，不使用未核实题凑数。
- 跨题包按conceptId去重，本局不重复；默认排除本设备已见题，历史题只在用户主动允许时重新进入题池。
- 每人一圈一次瞎掰人；普通人投中+1，瞎掰人按普通人投错票数加分。
- 上线之前完成规则测试、生产构建和手机宽度浏览器验证。

## 1. 文件与接口

src/games/registry.ts：大厅游戏登记。
src/games/bluff/types.ts：Config、GameState、Action、PublicView、PrivateView、Question。
src/games/bluff/engine.ts：创建游戏、发牌、动作验证、阶段推进、结算。
src/games/bluff/views.ts：公共信息及个人信息裁剪。
src/games/bluff/questions.ts：题包登记、合并筛选与容量检查。
src/games/bluff/packs/{wildlife,artifacts,customs,phenomena}.ts：分题材保存经过核实的题卡和来源。
src/games/bluff/questionHistory.ts：本设备按conceptId保存已见历史，重发和退出不清空。
src/session/{types,localSession,storage}.ts：统一会话契约、本地实现、版本化存档。
src/games/bluff/ui/{Setup,Reading,Speaking,Voting,Results}.tsx：阶段界面。
src/{main,App}.tsx、src/styles.css：挂载、大厅与移动端样式。
tests/{engine,views,storage,questions}.test.ts：关键逻辑测试。
scripts/test.mjs：编译纯逻辑测试至.test-build，运行node --test。

接口约定：

```ts
type Config = {
  playerCount: number; readSeconds: number;
  selectedPackIds: string[]; allowHistoryQuestions: boolean;
};
type Question = {
  id: string; conceptId: string; packIds: string[];
  term: string; explanation: string;
  category: string; difficulty: number; sourceUrl: string;
};
// GameState和Action由types.ts集中定义，所有动作带局/回合ID和事件序号。
// 状态包括phase、roundIndex、players、scores、assignments、usedQuestionIds、
// blufferSchedule、readerIndex、deadline、speakerIndex、votes与结算标记。
// Action覆盖开始阅读、结束阅读、下一发言人、开始投票、打开投票、
// 提交投票、整轮重发、下一轮；配置和错误动作均先验证再保存。
createGame(config: Config, questions: Question[], seed: number): GameState;
reduceGame(state: GameState, action: Action, now: number): GameState;
publicView(state: GameState): PublicView;
privateView(state: GameState, playerId: string, now: number): PrivateView | null;
```

PublicView无隐藏身份、解释或未公开票数；揭晓阶段才加入这些字段。PrivateView仅允许当前阅读者在到期前获取。

SessionAdapter提供getPublicView、getPrivateView、dispatch和subscribe。UI不直接访问完整GameState；未来联网时替换适配器，服务端不向客户端发放他人秘密。

开局先使用buildQuestionPool(config: Config, allQuestions: Question[], seenConceptIds: Set<string>): Question[]筛选选中题包、按conceptId去重，再按allowHistoryQuestions排除历史。createGame接收筛选后的题池快照，不在每轮重新读取可能变化的设置。词名首次展示时调用markSeen(conceptId: string): void并持久化，清空历史要求用户确认。历史存储失败时提示本设备无法保证跨局避重。
