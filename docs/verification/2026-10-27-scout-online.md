# SCOUT 联机验收

## 范围

原版规则 2–5 人，独立双人规则；六位房间码、个人暗牌、同回合并发确认方向、刷新恢复、教学和卡牌动画。保持旧游戏规则与协议不变，无新增依赖。

## 已取得证据

- 规则与房间测试原有 39/39；新增已关闭座位安全清理回归通过，保留新房间身份不被旧页面删除。UI 与教学测试 8/8。
- 现有 Python 题库检查：11/11。
- `node --experimental-strip-types scripts/verify-scout-online.ts`：真实 MQTT/WebSocket 双客户端四项检查通过，退出码 0。覆盖私有手牌、同时确认朝向、Show → Scout → Show、双人筹码及成员和房主刷新恢复。
- 初始建立连接改为房主先连接、成员随后连接，符合实际入桌顺序；游戏内朝向确认仍并发提交。并发建立命令行 WebSocket 曾出现握手失败，串行连接和浏览器双连接均成功。
- 浏览器使用 `127.0.0.1` 与 `localhost` 两个独立来源模拟两位玩家；真实创建房间、准备、开局、确认整手翻转、演出、三步挖角（翻转后插入中间）及继续演出已操作。

## 界面与教学

卡面按用户要求改成双色曲线分区、相向数字角标、薄边框，6/9 带方向标识，使用自行绘制的 SVG。七课教学已通过浏览器逐步实际操作，从整手旋转、连续顺子、挖角插牌、空隙合拢、后续顺子、挖角并演出，到清空手牌后的收据（5 收牌 + 2 筹码 = 7 分）。修复了示例物理牌分配耗尽导致教学白屏的问题。

390×844 手机模拟视口中，页面宽度 375、视口 390，无横向页面溢出；手牌与插牌间隙在内部横向滚动。实际操作首位、中央、末尾插入预览及取消/确认，明示示例检查普通出牌、回合等待、结算与完局。截图观察到旧舞台牌飞向收牌计数的过渡。

独立任务审查发现并修复：房间已关闭但本机记录未清理，刷新会等待不存在的房主；回首页再回房间会重复发牌动画。最终整体验收另外修复：不存在房间的加入请求可取消、手动编辑房间码清除旧邀请指纹、已确认方向不再重复应用翻转预览。两轮独立复核通过，无待处理 P1/P2。

最终版本：187/187 Node 测试、11/11 Python 检查、TypeScript、五入口构建与离线包资源检查通过。真实 MQTT 四项复测退出码 0。浏览器另行完成：保留房间返回后恢复不重播发牌，房主收桌 → 成员返回首页 → 刷新可重新开桌，以及不存在房间 → 取消入桌 → 刷新不残留座位。768 像素视口页面宽 766，无页面横向溢出。

## 验证边界

浏览器双来源仍是同一台电脑，不等同于不同地区网络或真机性能验证。多人规模由内存传输测试覆盖，真实网络脚本和当前页面试玩为双人。房主需要在线；无房主迁移。局面组件的明示本地示例只验证阶段布局与操作，不替代真实网络证据。

减少动态效果、隐藏页签快进与无 Web Animations 时静态降级已经实现并经代码审查；本轮没有切换用户系统动态效果设置进行现场验证。
